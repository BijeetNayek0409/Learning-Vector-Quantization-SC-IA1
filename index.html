Learn LVQ

What is LVQ?

LVQ is a classification algorithm. It does not keep the training data. Each class gets a few points called prototypes, and training moves them into good positions. To classify anything, you find the closest prototype and use its label.

What is a prototype / reference vector?

A prototype is a point in the same space as the data, with a class label attached to it. In this app they are the big diamonds. Training changes where a prototype sits. It never changes which class it belongs to.

Why is it supervised learning?

Because it needs the labels. The label on the training sample is what tells the algorithm to pull the winning prototype closer or push it away. K-means never sees labels, so it cannot make that decision.

How does LVQ classify a point?

Measure the distance from the point to every prototype, take the smallest, and use that prototype's label. The winner is called the Best Matching Unit (BMU). Because the rule is simply "nearest prototype", the decision regions come out with straight edges. They are Voronoi regions.

What happens when the winner is right, or wrong?

Right label: the prototype already represents this area well, so move it closer to the sample.

Wrong label: the prototype is sitting inside another class's territory, so push it away. The boundary shifts as a result. Those two cases are the whole training rule.

What do the learning rate and epochs do?

α sets the step size. At α = 0.1 the prototype covers 10% of the gap to the sample in one update. A large α learns quickly but jumps around; a small α is steadier but slow.

One epoch is one pass over all the training samples. More epochs usually give the prototypes time to settle. If decay is on, α shrinks each epoch, so early passes do the rough work and later ones only fine-tune.

Advantages, limitations, applications

Advantages: the model is tiny, just a few prototypes. Prediction is fast, and you can point at the exact prototype that made a decision. Extra classes cost nothing special.

Limitations: results depend on where the prototypes start and how many you use. Features have to be on similar scales, since everything is based on distance. Heavily overlapping classes are hard, and there is no guarantee of reaching the best possible boundary.

Applications: character and pattern recognition, medical signal and image classification, fault detection in machines, speech and sensor data. Generally, anywhere a small explainable classifier is worth more than a large one.

One update, drawn out

P1 is nearest, so P1 wins. Its label matches the input, so P1 moves toward the input by a fraction α of the gap. If P2 had won instead, it would have been pushed the other way. Open the Formulas & Algorithm Flow tab to watch this happen live.

Training loop

  1. Place the prototypes, one or more per class.
  2. Take the next labelled sample x.
  3. Find the distance from x to every prototype.
  4. The nearest one wins.
  5. Same label: move it toward x. Different label: move it away.
  6. Repeat for every sample. That is one epoch.
  7. Shrink α and run the next epoch.
  8. When training ends, classify new points by nearest prototype.

Formulas highlighted live while you step through training

1 · Euclidean distance

d(x, wi) = √( Σj ( xj − wij )² )

In 2D: d = √((x₁ − w₁)² + (x₂ − w₂)²). The winner is the prototype with the smallest d — the Best Matching Unit.

2 · Winner has the SAME class → move toward

wnew = wold + α ( x − wold )

The prototype takes a step of size α along the line pointing at the input.

3 · Winner has a DIFFERENT class → move away

wnew = wold − α ( x − wold )

Same step size, opposite direction: the intruding prototype retreats.

4 · Learning-rate decay (optional)

α(t) = α0 ( 1 − t / T )

t = current epoch, T = total epochs.

Viva questions 15 likely questions, with answers

1. What is Learning Vector Quantization?

A supervised classifier that represents each class with one or more prototype vectors. A new sample gets the label of the nearest prototype. Training adjusts where the prototypes sit so that this rule agrees with the training labels.

2. Is LVQ supervised or unsupervised? Why?

Supervised. Every training sample carries a label, and that label decides whether the winning prototype moves toward the sample or away from it. With no labels there is no direction to move in.

3. What is a prototype or reference vector?

A point in the feature space with a fixed class label. Training moves it around; its label never changes.

4. How is the winning prototype selected?

Compute the distance from the input to every prototype and take the smallest: winner = argmini d(x, wi). That prototype is the Best Matching Unit.

5. Which distance metric is used? Could you use another?

Euclidean, because it matches what you see on a 2D plot. Manhattan, Minkowski or weighted distances would also work. The choice matters, since the metric decides the shape of the decision regions.

6. What happens when the winner has the correct class?

Move it toward the sample: w = w + α(x − w). The prototype already represents that area, so this makes it a better representative.

7. What happens when the winner has the wrong class?

Move it away: w = w − α(x − w). It was intruding into another class's region, so pushing it back lets the correct class claim that area and the boundary shifts.

8. What is the role of the learning rate?

α is the step size. It decides what fraction of the gap between the prototype and the sample is covered by a single update, so it controls how much one sample can influence the model.

9. What if the learning rate is too high or too low?

Too high and the prototypes overshoot and keep oscillating near the boundary, and a single noisy sample can throw them off. Too low and training is slow, so they may never reach useful positions in the number of epochs you have. Decaying α is the usual compromise.

10. What is an epoch, and why train for several?

One epoch is one full pass over the training set. Each update only uses a single sample, so several passes are normally needed before the positions stabilise.

11. What is the difference between LVQ and K-means?

K-means is unsupervised. It has no labels and always moves the winning centroid toward the point, aiming to reduce the variance inside each cluster. LVQ has labels, and moves the winner toward or away depending on whether the labels match. K-means finds clusters; LVQ builds a decision boundary.

12. How does LVQ differ from k-Nearest Neighbours?

k-NN stores the whole training set and compares a new point against all of it. LVQ compresses it into a few prototypes, so prediction is much faster and needs far less memory. The trade-off is that some detail is lost.

13. How many prototypes per class should be used?

It depends on the shape of the class. One is enough for a single compact cluster. Curved or split regions need several, because each prototype only owns a straight-edged region. The concentric-rings dataset in this app shows that clearly: two prototypes give a poor boundary, eight do much better.

14. What are the advantages and limitations of LVQ?

Advantages: small and fast, easy to explain, handles several classes without any change, and the training rule is simple to implement.

Limitations: sensitive to the starting positions and to how many prototypes you pick, needs features on similar scales, offers no guarantee of an optimal boundary, and struggles when classes overlap heavily.

15. How do you know your code is really LVQ and not something else?

The algorithm sits on its own in js/lvq.js: distance, winner selection, and one update function whose sign comes from the label comparison. Nothing in that file draws anything. The arrows on the plot are drawn from the before and after coordinates recorded during the real update, so nothing is animated just for show.
